# Webman 开发

先读项目规则、composer.json/lock、start.php、process 配置和真实进程，区分 webman-framework、Workerman 和数据库适配包版本；[版本与来源](references/versions.md)。升级文档不等于现有项目必须升级。

## 常驻进程与版本

- 身份、租户、请求参数与连接不能放在跨请求全局/静态状态；复用控制器避免残留用户数据，日志上下文随请求/协程清理。
- 2.1 协程需要 PHP >=8.1、Workerman >=5.1、对应驱动与 eventLoop 配置，默认并未开启；不能仅见版本号就认定所有 IO 可并发。
- 2.1 数据库/缓存适配器增加连接池；事务使用同一连接、同一请求/协程，异常必须结束事务。不跨协程共享连接、事务或有请求状态的单例。
- 2.2 增加注解路由；只有目标版本和注册方式支持时使用，旧项目保留已有路由方式。
- 普通业务代码/配置通常 reload；进程配置或依赖变化通常 restart，以项目管理方式为准。不能把源码变化当成部署已生效。

## 实现与验证

按真实中间件建立认证、权限和数据范围，区分代理与客户端地址。返回框架 Response，不用 exit/die 结束 HTTP 请求。慢 IO 放入适当进程或队列，不把 sleep 当作协程等待。

数据库方言与迁移按项目约定，外部参数绑定，错误日志可定位且对外脱敏。查路由、Request/Response、模型、进程、Session 时按需读 [API 参考](references/api-guide.md)。验证语法、逻辑/接口及异常路径；并发身份/事务需交叉请求测试。不要擅自改全局 Composer 镜像或升级生产核心。
