# iv8 网页协议分析与环境验证

把浏览器观察、iv8 离线执行、独立 HTTP 请求分开验证。iv8 社区版模拟浏览器 API，不提供真实网络传输；接口存在不代表实现完整，也不保证通过网站风控。优先复用项目已有能力，普通 JSON/HTML 查询可直接使用 HTTP 客户端，无须强行引入 iv8。

## 先检查本地环境

1. 查看项目约定、依赖清单和锁文件，检查实际解释器、操作系统、CPU 架构、虚拟环境及 iv8 版本。不要凭 `python` 命令名判断版本。
2. **找不到本地环境或 import iv8 失败时，先读 [环境创建与排障](references/environment.md)，向用户说明缺少什么，并给出当前系统可直接执行的命令。** 在已授权的项目范围内可直接创建隔离环境、安装并验证；需要用户操作的终端或系统安装步骤，给出准确命令及下一步，不能只说“先装 iv8”。已有环境不删除、不自动升级全部依赖，也不把系统 Python 当作安装目标。
3. 用项目解释器执行本 skill 的 `scripts/check_environment.py`；脚本只做离线探针，不安装软件、不读取业务 Cookie、不请求网站。返回 0 表示探针通过，1 表示运行检查失败，2 表示缺少 iv8；JSON 中记录解释器、版本与各项结果。原生扩展崩溃或超时时按环境/兼容性问题处理，不能当作站点签名失败。部分版本会在 JSON 报告前打印原生 banner，自动处理时不要把整段 stdout 当作纯 JSON。
4. 网络客户端、GUI、HTML 解析等依赖按实际任务安装。逐项处理环境检查结果，再单独验证目标脚本；已知与目标无关的 API 差异可记录后继续，不能隐去失败项或盲目重装。

## 从成功的浏览器请求建立基准

使用当前工具允许的浏览器网络/页面能力观察用户有权访问的目标站点；不要将旧对话中的浏览器 API 当成当前接口。无登录会话时先引导用户在真实浏览器登录。

记录请求方法、最终 URL、参数、body 编码、必要请求头、Cookie 属性、响应类型、业务码、分页及关键记录。区分浏览器内 fetch 与脱离浏览器的 HTTP。观察网站是否有自动保存偏好或其他写副作用；分析查询不扩大为提交、申报或业务更新。

先读实际加载脚本和请求构造链，再判断是普通编码、加密、摘要、动态签名还是硬件签名。函数名 `checkUkey`、`sign` 或压缩混淆程度不是结论。优先提取最小依赖函数，避免整页旧 jQuery 初始化失败阻断纯函数验证。

## 在 iv8 中离线复现

- 使用 `with iv8.JSContext() as ctx` 管理生命周期；按所装版本核对 `environment`、`mode="debug"`、`page.load` 和事件循环 API。
- 用虚构数据验证加解密往返、URL/form 编码、签名输入与输出。Python 值通过 `json.dumps()` 等序列化进入 JS，勿直接拼接原始业务字符串。
- 对照浏览器同一输入，固定时间戳、随机数与参数顺序后逐字比较；核对空值、Unicode、空格、`+`/`%20`、百分号和 JSON 序列化差异。真实请求再更新时效参数。
- 运行未验证的整页或第三方 JS 时，用有超时、内存/进程边界的独立实验进程，避免原生崩溃或无限循环拖垮宿主。不要直接暴露文件系统、shell 或业务凭据给目标脚本。
- 对实际缺失或行为不同的 API 做最小补充；`typeof` 存在仅是接口探针，DOM 内容、storage、crypto、事件循环及目标签名要执行验证。报告声明实际测到的范围。
- 异步回调需按文档推进事件循环；社区版 fetch/XHR 应通过离线资源注入或由独立 HTTP 层处理，不把模拟响应当成真实服务端结果。
- 硬件证书、UKey、电子口岸 `EportClient.signData` 等真实签名仍依赖对应客户端与设备。mock 只能证明调用和参数传递，不能证明真实签名可用。

## 独立 HTTP、人工验证与接入

1. 从用户正常登录的浏览器更新获授权的会话；保留 Cookie 的 domain/path/expiry/secure 等属性及必要 CSRF/会话字段，避免压平成全站通用 Cookie。限定请求目的站点，检查重定向后再发送敏感信息。
2. 先做一次只读请求，设置超时、响应大小上限并检查 HTTP 状态、内容类型和业务结果；HTTP 200 也可能是登录 HTML 或风控码。对照浏览器条数、标识、字段与分页。
3. 签名正确仍被拒绝时，按证据比较新会话、请求头、参数/body 字节、HTTP 版本、代理出口与传输差异。HTTP/2 是可验证因素，不能承诺它普遍解决风控；不要反复重放旧签名。
4. 出现验证码、登录失效或明确风控码（如 `MSG_SAFE_0001`），暂停采集，保留进度，将用户带到真实可操作的验证页面。命令行只输出“请完成验证”不足以构成可用流程。验证后重新读取会话，做一次请求确认，再恢复。默认人工验证；不把历史上的一次 OCR 成功推广为通用自动过验证码方案。
5. 用户要求桌面软件时，可按宿主选择内嵌浏览器或专用外部浏览器，交付明确的打开验证、完成验证、更新会话和继续采集入口；不要假设不同浏览器共享 Cookie。Web 后台用可操作的远程浏览器会话，并隔离账号、租户、操作人和过期窗口，避免旧验证覆盖新会话。
6. 分页/批量取数在少量真实比对通过后扩展，保存进度和每页结果，支持暂停续采；原始数据与去重视图分开，明确总数、已取数、重复与缺失。不把两页成功说成全量稳定。

会话文件使用私有目录及系统支持的受限权限，加入忽略；日志和仓库不含账号密码、Cookie、token、真实业务响应或浏览器 profile。交付业务集成时优先沿用宿主语言/HTTP 层；验证出只是标准编码时无需额外部署 iv8。

## 结果与参考

分别报告：环境能运行、目标 JS 可执行、与浏览器输出一致、独立 HTTP 成功、完整业务流程/全量稳定性。每个结论注明实际证据及未验证范围。

分析知识产权备案库、盐田、报关易、一达通或 FastMoss，或需要判断“是否真的需要 iv8”时，读 [历史案例与决策](references/cases.md)。案例仅保留脱敏技术结论，历史接口必须按当前网站复核。
