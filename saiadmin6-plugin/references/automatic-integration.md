# 安装、升级自动接入与卸载

## 默认交付契约

用户在插件管理上传 ZIP 并安装或升级，即应完成插件运行所需的宿主接入。语言注册、入口加载等不能依赖开发机残留、用户手工改宿主或额外运行 Python/PHP/shell 接入脚本。可保留只读预览及修复工具，但正常安装不能依赖它们。若当前目标缺少可用机制，继续实现受支持的自动接入；实际阻塞须报告未完成，不以手动步骤替代完成。

优先级：宿主原生插件发现/注册 → 正式安装/升级/卸载钩子 → 核实顺序后用插件迁移调用接入服务。已有原生机制能解决时，不额外修改宿主源文件。默认不修改核心安装器，不在应用启动、配置加载、迁移构造/init 或状态查询中隐式写文件。

系统菜单/按钮/API 权限点及适用的数据范围也是默认接入项，详见 [权限接入](permissions-data-scope.md)。安装前检查宿主能力，自有权限随迁移注册，共享角色/部门与 DataScope 依赖不归业务插件卸载；不能通过复制参考包的核心覆盖文件或要求手工执行固定 ID 的 SQL 完成接入。

依赖安装与生产构建沿用宿主原有流程；源码接入自动化不等于替宿主完成构建或部署。尽量使用插件现有运行时实现安装服务，避免为接入再引入 Python 或 shell 依赖。

## 迁移调用服务的落点

在目标安装器代码中确认：何时复制文件、何时运行迁移、升级如何选择未执行迁移、卸载回滚顺序、依赖完成与安装状态、前端目录解析方式。只有语言入口等文件已复制，接入服务才能引用它们。

已验证的 Phinx 安装分支：复制插件文件 → migrate（首装/升级）→ 依赖和安装状态；卸载为逆序回滚 → 删除文件。可以在新增迁移的 `up()` 调用插件自己的接入服务，在 `down()` 中先完成数据检查再调用移除服务。接入逻辑放在可单独验证的服务中，不散落在迁移里。可提供 `plan()`（只读）、`apply()`、`remove()` 等职责；重复调用应幂等。

Phinx 只执行未应用的迁移，不能依靠修改旧迁移触发升级接入。后续只更新语言资源时可沿用已安装入口；接入契约变更则追加迁移调用幂等服务。失败时传播错误并核对该迁移和连接的事务状态，尤其 PostgreSQL，不遗留 idle in transaction；不能吞错后仍报告安装成功。文件、DDL、依赖安装不构成全局事务，必须分别核对。

## 必须修改宿主文件时

1. **路径与预检**：复用目标安装器解析的目录。已验证的安装器提供 `InstallLogic::frontendDir()` 并读取 `FRONTEND_DIR`，不要硬编码临时目录或假定宿主始终叫 saiadmin-artd。检查目标文件、注册资源、已支持的源码结构及全部写入权限，先生成完整计划再写入；未知结构明确失败，不猜测套用。
2. **最小管理范围**：只加入本插件命名空间和带明确标记的最小片段。不得覆盖共享语言文件、默认 locale/fallback、其它插件或页面行为。入口随可安装的插件子树分发；如用可选 glob，必须验证装入时能加载、移除后不产生缺失模块错误。
3. **备份与写入**：将原文件、状态保存在插件被升级替换的目录之外，例如 `runtime/<app>/frontend-integration/<宿主目录哈希>/`。锁定本插件的接入过程，按内容备份，限制备份权限；使用同目录临时文件原子替换，尽量保留文件权限。写前复核原内容，支持宿主实际换行/编码及含中文、空格的路径。
4. **失败回退**：后续文件或状态写入失败，回退本次已成功写入且尚未被其它进程修改的文件。若内容又发生变化，不用旧快照强行覆盖，报告相关路径与备份。安装保持可诊断的失败状态，修复原因后按真实状态恢复，不伪造 state。
5. **旧版接管**：仅识别已知旧版导入/保护写法，接管后统一管理，避免重复注册与重复包裹。升级同时覆盖旧版已手动接入、未接入两种情况；无法识别的自定义修改不能静默覆盖。无需迁移旧写法的插件不必凭空增加兼容层。

如果宿主切换语言会重载页面，需按实际实现避免插件内未保存输入丢失。Board Studio 的做法仅对自身路由跳过 `reload(50)`，保留 locale 更新、用户语言持久化与其它页面刷新；这不是所有宿主都必须套用的补丁。

## 卸载与数据保留

- 先按插件的数据策略判断能否卸载，再改宿主或删表/菜单。默认有业务数据时拒绝破坏性卸载，检查包括软删除、历史版本、发布记录、数据集与归档等实际存在的表；已有明确授权的数据清理策略按项目约定执行。
- Phinx 最新迁移最先回滚，数据保护需位于最早可能清理资源的位置。不能先移除语言入口再在更早迁移中发现业务数据并拒绝卸载。
- 移除本插件管理片段并恢复该片段替换的原行为，保留用户安装后新增的代码。不用整份历史备份覆盖宿主当前文件。管理片段被用户改动时拒绝自动清理并给出诊断信息。
- 移除已完成时再次执行应安全；保留运行时备份供诊断。卸载后宿主无悬空引用并能构建，重新安装无需旧插件目录或手动修复。

## 验证与交付

使用 [生命周期验收](acceptance.md) 的最终 ZIP 在独立环境验证；声明支持多数据库时分别覆盖：

- 首装前没有插件残留，全程不运行接入命令，安装后验证注册实际生效；随后按真实依赖安装流程完成状态，不以伪造依赖完成绕过安装。
- 同版本上传行为、重复接入幂等、卸载重装；升级保留业务记录，并在有旧版接入历史时覆盖两种状态。
- 有数据拒绝卸载时宿主文件逐字节不变；空库卸载只清理自身片段，安装后新增的用户代码保留，宿主仍可构建。
- 需要写宿主的插件测试不支持结构、不可写文件、后续写入失败与管理片段被修改；核对无半成品、事务已关闭、原因修复后可恢复。纯服务测试可覆盖故障注入，但不能替代 ZIP 安装生命周期测试。

安装手册将接入写成自动行为。可选修复命令与正常步骤分开，并明确宿主原有依赖/构建流程。源码、示例和测试入口不引用本次临时实验室路径或账号。

## 2.2.0 权限接入补充

角色授权树若未调用宿主菜单翻译器，自动接入覆盖该最小标签片段；PG 角色菜单 API 若重现 bigint 批量问题，仅对已核对语句提供兼容。前后端全部目标在同一计划预检/备份/写入/回退；新增第四个目标时不能沿用只覆盖前两个文件的旧测试。契约变更追加迁移，不修改已执行迁移；先检查全部业务表，再清理授权与管理片段。失败时关闭迁移事务，原生已修复与未知实现分别处理。条件与来源见 [实测排错](runtime-pitfalls.md)，不默认给其它插件套用该后端修复。
