# 插件生命周期验收

| 场景 | 操作 | 必须观察 |
|---|---|---|
| 全新首装 A | 初始化核心，上传发行 ZIP，安装，处理依赖 | installed 状态、后端及前端文件、业务表、菜单/按钮、页面与接口成功 |
| 同版本重复上传 | 在 A 再上传原 ZIP | 明确拒绝/当前版本预期，现有文件、数据、状态不损坏 |
| 有数据卸载 | 创建业务记录，按插件声明策略尝试卸载 | 默认拒绝破坏性卸载时，数据、菜单及宿主接入均保持不变；不能先移除接入再拒绝 |
| 空库卸载→重装 A | 按授权清理临时测试记录，卸载，同 ZIP 再导入 | 仅清理自身资源/接入，保留用户其它修改；无悬空导入，宿主可构建；重装无重复表/菜单/权限/接入 |
| 干净首装 B | 新 create，不复用 A 的可写目录/卷 | 同 ZIP 安装成功，A 的标记数据在 B 不存在 |
| 升级 | 旧 ZIP 安装并写记录，上传递增版本 ZIP；旧版有手动接入历史时，分别覆盖已接入/未接入 | 接入自动完成、新代码生效、废弃文件消失、迁移只执行预期次数、旧业务记录保留 |
| 新版本直接首装 | 另一干净实验室直接装新 ZIP | 无需依赖旧版残留即可建立完整结构 |
| 安装失败 | 使用有意失败的测试包（仅一次性环境） | 错误可定位，记录文件/DB/state，修正后可恢复；不能以假状态算成功 |
| 自动接入 | 最终 ZIP 首装、升级、重装，全程不先运行接入脚本或手工改宿主 | 必要注册与入口自动生效，幂等、备份/状态可核对；可选修复工具的测试与本场景分开 |
| 接入失败与清理保护 | 需要修改宿主的插件：测试未知结构、不可写文件、后续文件写入失败及用户修改管理片段 | 无半成品修改/静默覆盖；修正后可恢复，不遗留数据库事务；用户其它改动在卸载后保留 |
| 依赖 | 在无插件依赖的基线安装 | 声明及锁一致，无依赖漏装，前端重启/构建和后端加载成功 |
| 主题 | 宿主明暗主题及可配置主色切换 | 后台页面/弹窗/图表遵循宿主 token，无全局覆盖；用户画布配色不被改写 |
| 多语言 | 不刷新切换宿主支持语言，并以最终 ZIP 全新安装 | UI、表头、校验、提示同步翻译，词条完整，无缺失键，业务输入保持不变 |
| 功能权限 | 有菜单无动作权限、无菜单及动作权限直接请求，以及获准动作的普通账号 | 页面/按钮与后端检查编码一致，未授权 API 拒绝，覆盖自定义操作 |
| 数据范围 | 普通角色分别配置全部、自定义部门、本部门、本部门及子部门、本人 | 列表/总数/详情/修改/删除/导出/统计范围一致，联表及批量无旁路；共享资源记录实际策略与不适用原因 |
| 归属与缓存 | 伪造归属、混合 ID、子资源；变更角色/部门；同实例切换账号 | 服务端赋值、普通更新不转移所有者，租户/业务条件有效，部分成功不冒充整批成功，缓存与实例状态不串权限 |
| 权限生命周期 | 首装、旧版升级、卸载；提供授权管理能力时测试目标角色与部门/菜单子集 | 自身权限点幂等、保留已有授权；共享角色/数据权限入口不被清理，配置不能越权扩大范围 |

独立性验证：A 写入唯一记录或标记，B 查询没有；两个 Compose 项目的 network/volume 标签不同，分别的 bind source 路径不同。只看端口不同不充分。

升级、故障注入和依赖测试按插件能力适用范围开展，标明不适用原因。至少一次基于 ZIP 的逻辑层测试；插件管理前端有改动或交付可见页面时做浏览器完整路径。复测要使用最终打包后的文件，不能仅测 staging。

权限测试的数据构造、五种范围及参考包差异见 [权限点与 DataScope](permissions-data-scope.md)。包含无角色、空自定义部门、缺失部门、多角色，以及创建者伪造与越权 ID 请求；仅安装 DataScope 或仅管理员验证不算业务接入通过。

有界诊断：`compose LAB logs --tail 100 backend frontend db`；核对 runtime/saipackage/<app>/info.ini、实际文件、迁移记录、表和菜单；检查前端 Console/Network。请求失败后先查状态，勿立即再点安装。若安装中 reload 导致断连，先验证服务和状态，不推定数据库事务回滚。

报告逐项使用“通过 / 失败 / 未测 / 不适用”，注明逻辑层、HTTP、UI 层次。容器存活、PHP lint、前端 build 只分别证明环境/语法/构建，不能替代业务测试。
