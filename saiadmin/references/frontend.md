# 前端主题、多语言与发行

生成前先查宿主主题 token、明暗切换、组件封装、i18n 初始化、支持语言和持久化。使用相邻页面确认约定，不发明统一 CSS 变量名、翻译 API 或目录。

后台布局、表格、按钮、表单、弹窗使用宿主语义背景、文本、边框、状态色和主色。Canvas/图表按实际 token 解析并监测变化；用户设置的画布颜色与业务标题不随后台切换重写。禁止用全局主题覆盖让单个插件“看起来适配”。

业务页面复用宿主 Composer 与独立命名空间。示意（t 取自宿主的 useI18n，目标 Composer 已完成资源注册）：

```ts
const { t } = useI18n()
const columns = computed(() => [
  { prop: 'name', label: t('orders.fields.name') },
  { prop: 'status', label: t('orders.fields.status') },
])
```

标签、placeholder、空态、错误、校验、确认框、提示与可访问文案都需覆盖宿主语言；组件库 locale 与业务语言同步。不能将 t() 在 setup/模块作用域求值一次后保存成固定数组，也不能通过重载整个编辑器实现翻译更新。保留宿主 locale、fallback 和其它页面行为。

语言资源及注册入口必须位于安装器实际复制的插件目录内。必要的宿主接入由安装/升级自动完成：优先原生注册或钩子，核对安装顺序后才使用版本迁移调用幂等服务；预检、备份、失败回退与卸载清理只管理自身片段。卸载先判断数据策略，拒绝卸载时不能先拆掉接入。可选诊断工具不成为正常安装必跑脚本。

测试最终 ZIP 全新安装和升级后的词条加载，实际切换明/暗、主色、语言，保留未保存输入与用户画布配置；检查长译文、表头、动态提示和校验。已有中文模板只说明结构，不是最终可直接交付的本地化页面。
